# Quota（订阅流量）
**让你清楚你的节点还有多少流量。**

一个只干一件事的小安卓应用：把订阅链接里的额度信息读出来，显示**剩余流量**和**到期时间**。
包名：`com.gukangran.subtraffic`
当前版本：`2.8`（versionCode 19）
作者：gukangran2026-source
最低系统：Android 5.0（minSdk 21），targetSdk 34

---

## 一、原理（为什么能看到剩余流量）

向订阅链接发一次普通 GET 请求，读取服务器返回的 **响应头** `subscription-userinfo`：

```
subscription-userinfo: upload=1073741824; download=2147483648; total=107374182400; expire=1800000000
```

- 单位是**字节**，`expire` 是 Unix 秒级时间戳。
- 约定（各家客户端一致）：`total=0` 视为**不限量**，`expire=0` 视为**不过期**。
- 剩余 = `total − upload − download`。

这是机场面板（Marzban / X-UI / Vboard / Xboard 等）下发的标准头，Hiddify、v2rayN 等客户端也是这么读的。
**前提：机场确实下发这个头。** 不发的话本应用无法得知额度，界面会明确显示「服务器未下发流量信息」。

顺带读取的头：

- `profile-title`（订阅名称，支持 `base64:` 前缀）→ 用作列表标题。

本应用**不解析节点、不代理流量、不上传任何数据**，结果只存本机 SharedPreferences。

## 三、构建

```bash
bash /root/subtraffic/build.sh
```

产物：`build/SubTraffic-v1.0.apk`（签名后约 29 KB）。

本机（aarch64 proot 环境）的几条特殊处理，换环境时要注意：

1. **aapt2 用的是原生 ARM 版** `/root/android-arm-aapt2/aapt2`。
   build-tools 里自带的 aapt2/aapt/zipalign 都是 x86_64，在这台 ARM 设备上跑不起来。
2. **zipalign 用 `tools/zipalign.py` 替代**（给未压缩条目补 padding extra field）。
3. `d8` 和 `apksigner` 本身就是调用 java 的 shell 脚本，可直接用。
4. 整套流程**不依赖 Gradle、不联网下载依赖**。
5. aapt2 link 时资源包要作为**位置参数**传入，用 `-R` 会被当成 overlay 报错。

**升级步骤**：改 `AndroidManifest.xml` 里的 `android:versionCode`（每次 +1，versionName 同步改）→ 重跑 `build.sh`。
只要钥匙不变，新包可以**直接覆盖安装**，不用卸载、数据不丢。
钥匙一旦丢失或换新，就必须先卸载旧版才能装。

## 五、怎么用

- 右上角三个圆钮，从左到右：**🔍** 搜索、**＋** 添加、**⋮** 设置菜单（三个点在**最右边**）。
- 搜索不是弹窗：那个 **🔍 圆球本身就是搜索栏**。点它，同一个形状从球的位置**向左拉伸**成一条搜索条（纯宽度变化，没有缩放、没有淡入淡出，标题和图标都不动），左端停在「订阅流量」右边。
- 搜索条里左边是放大镜、中间是「搜索」提示文字、**最右边是「×」**；点「×」（或再点放大镜、或按返回键）用**同一套动画反向缩回**成原来的圆球。
- 点 **⋮** → **「优先显示已用」/「优先显示剩余」**：切换蓝色大数字显示哪个指标。选「已用」时大数字变成已用流量，详情行换成显示剩余；菜单文字会跟着变成相反那一项，点回去即恢复。
- 卡片右上角「正常 / 不限量」胶囊**左边有个刷新按钮**：点它只刷这一条；刷新时按钮自己转、胶囊显示「正在刷新」，旧数据不会被清空。
- 点 **⋮** → **「字体大小」**：小 / 标准 / 大 / 特大，卡片文字和顶部标题一起缩放。
- 详情页 → **「重命名」**：给这条订阅起个自己的名字（留空恢复默认）；名字存在本地，刷新不会把它覆盖。
- 点 **＋** → **从底部滑出「添加订阅」面板** → 粘贴链接（面板里有「粘贴」按钮可直接取剪贴板）→「添加并查询」。
- 右下角有个圆形按钮：**一键刷新所有订阅**（有查询在跑的时候它自己转）。
- **冷启动**（进程重开）时会自动查一次余额；从后台回到应用不刷。
- 点 **⋮** → **「主题」**：跟随系统 / 浅色 / 深色（Android 12+ 是应用级夜间模式，只影响本应用）。
- 卡片顶部是整块彩色（蓝=正常、绿=不限量、红=即将用尽、灰=未取到），白色大字显示剩余流量；
  下方白色区固定三行（总量 / 已用、上下行、到期时间），加一条用量进度条和一行状态。
- **刷新时卡片右上角显示「正在刷新」**（全量匹配时显示「匹配方式 3/12」），**旧数据一直保留在卡片上**，不会变空、不会跳大小。
- 条目本身点击不做任何事（避免误触）；每张卡片右下角有「详情」按钮。
- **锁定方式**：添加订阅时自动逐个试各种方式（直连 + 常见客户端标识 + 本机代理端口），
  命中后把该方式锁定在这条订阅里；之后每次刷新（卡片上的刷新按钮、菜单里的「立即刷新」）**只走锁定方式**，一次请求完成。
  锁定方式失效时状态行会提示，进「详情」点「重新验证方式」重跑全部方式即可。
- **刷新方式**：**没有任何自动刷新**（v2.2 移除定时刷新，v2.3 又移除了「回到前台刷一次」）。只有你手动点才会刷：卡片上的刷新按钮、菜单里的「立即刷新」、详情页的两个刷新按钮，以及新添加一条订阅时。
  刷新**只走已锁定方式**，还没锁定方式的订阅会被跳过。
- **详情**（卡片右下角按钮）：显示已锁定方式、每次尝试的结果、`subscription-userinfo` 原始值、响应体片段，
  并提供「重新验证方式 / 立即刷新 / 复制详情 / 删除」。
- **升级保留数据**：存档格式向后兼容，旧版本记录照样能读出来（有专门的自检项验证这一点）。

## 八、更新记录

### v2.8（versionCode 19）
- **遇到限流立刻停手**：服务器返回 HTTP 429（请求太频繁）时，原来会把 12 种方式全部试一遍，等于在限流上又连打 11 次，越打越久。现在第一次拿到 429 就停止，并在卡片上标「限流」，60 秒内再点刷新会提示等待。
- **失败原因分开说人话**，不再混成一句「没取到流量信息」：
  - 「限流」= 服务器嫌请求太频繁，链接本身没坏，等几分钟再刷；
  - 「链接失效」= 服务器明确说链接失效/过期（如 `Subscription link is invalid or expired`），要去面板重新复制；
  - 「令牌被拒」= `token is error` 这类明确拒绝；
  - 其余才是网络/代理问题。
- **刷新失败不再清空已有数字**：限流、断网、链接失效时，卡片继续显示上次成功刷到的流量，状态行补一句「数字为 xx:xx」并说明本次为什么没刷到。
- 修 `isTokenRejected` 的误判：带 `error`/`token` 字样的整页 HTML 不再被当成「令牌失效」。
- 新增 `tools/RateTest.java`：429 / 链接失效 / 令牌被拒三种判定的回归测试（9 项）。
